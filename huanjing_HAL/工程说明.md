# 智能环境监测工程说明与技术手册

## 1. 工程是什么

这是一个基于 **STM32F103ZET6** 的环境监测与 A/B OTA 工程。STM32 读取温湿度、光照和空气质量，在 LCD 上显示；Arduino 程序烧录的 ESP32-C3 负责华为云连接、环境上报和 OTA 固件下载。

工程使用：

- STM32CubeMX：配置时钟、引脚、ADC、I2C、FSMC、USART 和 FreeRTOS。
- STM32 HAL：用统一函数操作外设，例如 `HAL_I2C_Master_Receive()`。
- FreeRTOS（CMSIS-RTOS v2 接口）：让传感器、LCD、环境上传和 OTA 并行工作。
- Keil MDK：编译、下载和调试。

当前 LCD 有两个页面：环境仪表盘和 `SYSTEM STATUS` 系统状态页。第二页显示 Wi-Fi、MQTT、OTA 进度、结果消息和当前固件版本。

## 2. 当前外设与引脚

| 功能 | 外设/引脚 | 用途 |
| --- | --- | --- |
| DHT11 | PC3 | 温湿度单总线数据线，低电平开始信号、输入读取应答和数据。 |
| BH1750 | I2C1：PB6/PB7 | PB6 是 SCL 时钟，PB7 是 SDA 数据，用于读取光照。 |
| MQ135 | ADC1 通道 10 | 模拟电压转换为 ADC 原始值，再换算为显示用空气质量数值。 |
| LCD | FSMC | 使用并行总线快速写 LCD；相关引脚由 CubeMX 的 FSMC 配置管理。 |
| KEY1 | PF8 | 上拉输入，按下为低电平，用来切换 LCD 页面。 |
| ESP32 UART | USART2：PA2/PA3 | PA2 为 STM32 发送、PA3 为 STM32 接收，传递普通文本。 |
| ESP32 使能 | PE4 | 拉高后允许 ESP32 模块工作。 |

> 串口连接必须交叉：STM32 的 PA2（TX）接 ESP32 的 RX，STM32 的 PA3（RX）接 ESP32 的 TX，并且两块板必须共地。

## 3. 目录和文件职责

### 3.1 CubeMX 生成的文件

`Core/Src/adc.c`、`i2c.c`、`usart.c`、`gpio.c`、`fsmc.c` 负责外设初始化。它们的配置来自 `42_lcd_hal.ioc`，重新生成代码时可能被更新。

不要把自己的业务流程直接写进这些初始化函数主体。需要增加少量初始化调用时，写在 `/* USER CODE BEGIN ... */` 和 `/* USER CODE END ... */` 之间。

### 3.2 自写业务模块

| 文件 | 作用 | 对外常用函数 |
| --- | --- | --- |
| `dht11.c/.h` | DHT11 单总线时序与校验 | `Dht11_Init()`、`Dht11_Read()` |
| `bh1750.c/.h` | BH1750 I2C 光照读取 | `Bh1750_Init()`、`Bh1750_ReadLux()` |
| `mq135.c/.h` | MQ135 ADC 采样 | `Mq135_Read()` |
| `env_sensor.c/.h` | 汇总三种传感器数据 | `EnvSensor_Init()`、`EnvSensor_Update()` |
| `app_key.c/.h` | KEY1 消抖和按下事件 | `AppKey_Init()`、`AppKey_PageTogglePressed()` |
| `app_ui.c/.h` | LCD 环境页和系统状态页 | `AppUi_Init()`、`AppUi_Render()` |
| `esp32_uart.c/.h` | 中断环形缓冲区和 UART 传输 | `Esp32Uart_ReadByte()`、`Esp32Uart_SendString()` |
| `user/OTA` | A/B OTA、Flash、元数据和完整性校验 | `OtaUart_Process()`、`OtaApp_ConfirmRunning()` |

模块封装的作用是：使用模块的人只需要知道“调用什么函数”，不需要同时理解 I2C 寄存器、DHT11 微秒时序或 LCD 写显存细节。例如 UI 任务只调用 `AppUi_Render(&environment, &esp32_status)`，不直接读取 UART 或传感器硬件。

## 4. 快速使用流程

1. 在 CubeMX 打开 `42_lcd_hal.ioc`，确认 MCU、外设和 FreeRTOS 配置正确。
2. 生成代码后，打开 `MDK-ARM/42_lcd_hal.uvprojx`。
3. 在 Keil 中执行 Rebuild，确认没有编译错误。
4. 下载 STM32 程序。LCD 首先由 `LCD_Init()` 初始化，随后 FreeRTOS 启动，UI 任务会显示环境页。
5. 如果没有接传感器，LCD 对应位置显示 `NO DATA`。这是读取失败后的正常提示，不是模拟数据。
6. 按 KEY1（PF8）可在环境数据页和 `SYSTEM STATUS` 系统状态页之间切换。

## 5. FreeRTOS 四任务

### 5.1 任务分工

| 任务入口 | 周期 | 只负责什么 | 为什么这样分 |
| --- | ---: | --- | --- |
| `StartDefaultTask`（`sensortask`） | 1000 ms | 读取三种传感器 | 传感器更新不需要很快；一秒一次够用，也减少 I2C/ADC 访问。 |
| `StartTask02`（`uitask`） | 500 ms | 读取 KEY1、刷新 LCD | 页面切换和显示比传感器更新稍快，操作手感更稳定。 |
| `StartTask03`（`uarttask`） | 1000 ms | 复制环境快照并发送 `ENV` | 只负责上行遥测；OTA 忙时暂停，避免协议互相干扰。 |
| `StartOtaTask`（`otaTask`） | 1 ms | 调用 `OtaUart_Process()` 并确认新固件 | 单一消费者持续清空 UART 环形缓冲区，完成 STATUS 和 OTA 解析。 |

数据流如下：

```text
传感器任务 -> latestEnvData 共享副本 -> UI 任务 -> AppUi_Render() -> LCD
遥测任务 -> 复制环境快照 -> Esp32Uart_SendString() -> ESP32/华为云
USART2 中断 -> 256 字节环形缓冲区 -> otaTask -> OtaUart_Process()
                                            ├─ STATUS -> SYSTEM STATUS 页面
                                            └─ OTA 帧 -> 非活动 Flash 槽位
KEY1 -> UI 任务 -> AppUi_TogglePage() -> 切换显示页面
```

### 5.2 为什么任务中使用 `osDelay()`

`osDelay()` 会让当前任务进入等待状态，把 CPU 让给其他已就绪任务。例如 LCD 任务等待 500 ms 时，OTA 任务仍能每 1 ms 清空串口缓冲区。

普通业务循环中不要用 `HAL_Delay()` 长时间等待，因为它会占住当前任务。DHT11 的 `HAL_Delay(18U)` 是一个例外：它是单次读取开始信号的硬件时序，且只发生在传感器任务中。

### 5.3 为什么传感器初始化放在任务里

`EnvSensor_Init()` 在 `StartDefaultTask` 中调用，而不在 `MX_FREERTOS_Init()` 中调用。

原因是未连接 I2C 传感器时，初始化或读取可能等待总线超时。如果调度器启动前就在初始化，LCD 和其他任务可能迟迟无法运行。把它放进传感器任务后，FreeRTOS 已经启动，其他任务仍能运行和显示页面。

## 6. 共享环境数据与临界区

传感器任务写数据、LCD 任务读数据。如果一个任务正在写温度，另一个任务正好读湿度，可能得到“半新半旧”的一帧数据。

因此 `freertos.c` 使用 `taskENTER_CRITICAL()` 和 `taskEXIT_CRITICAL()` 包住结构体复制：

```c
taskENTER_CRITICAL();
latestEnvData = *environment;
taskEXIT_CRITICAL();
```

这段临界区只复制一个很小的 `EnvData_t` 结构体，时间很短。它的作用是让复制操作不可被其他任务打断，从而保证 LCD 得到完整的一帧数据。

不要在临界区内调用 LCD、I2C、ADC、串口或 `osDelay()`：这些操作可能很慢，会让其他任务等待太久。

## 7. 传感器技术说明

### 7.1 DHT11

DHT11 使用单根数据线。STM32 先把 PC3 配为输出，拉低至少 18 ms 作为开始信号；随后把 PC3 切回输入，等待传感器回应并读取 40 位数据。

40 位数据依次是湿度整数、湿度小数、温度整数、温度小数和校验和。`Dht11_Read()` 最后比较前四个字节之和与校验和；不相等时返回 `false`。

该模块使用 DWT 周期计数器实现微秒延时，因为 DHT11 的高低电平宽度是微秒级。调用者不需要处理这些细节，只需要检查 `Dht11_Read()` 的返回值。

### 7.2 BH1750

BH1750 通过 I2C1 通信，地址为 `0x23`。`Bh1750_Init()` 先发送上电命令，再设置连续高分辨率模式。之后 `Bh1750_ReadLux()` 读取两个字节，并按数据手册将原始值换算为 lux。

如果 I2C 没接线、地址不对或设备无响应，HAL 函数返回错误，模块返回 `false`；环境汇总模块把 `light_valid` 设为 `false`，UI 显示 `NO DATA`。

### 7.3 MQ135

MQ135 输出模拟电压，ADC1 的通道 10 读取该电压。`Mq135_Read()` 启动 ADC、等待一次转换、读取原始值并停止 ADC。

当前 `estimated_ppm` 是把 ADC 的 0~4095 线性映射到显示用 0~1000 的数值，用于观察空气质量变化趋势。它不是经过气体浓度标定的真实 ppm；若需要准确浓度，必须根据传感器型号、负载电阻、预热时间和目标气体进行标定。

### 7.4 `EnvSensor_Update()` 的作用

`EnvSensor_Update()` 依次调用 DHT11、BH1750 和 MQ135 的读取函数，更新 `EnvData_t`：

```c
EnvSensor_Update();
const EnvData_t *data = EnvSensor_GetData();
```

每一个数据都有对应的 `*_valid` 标志。这样即使只接了其中一个传感器，其余数据也不会被伪造成正常值。

## 8. LCD 与按键

### 8.1 为什么 LCD 不每次整屏刷新

`app_ui.c` 把固定内容和动态数值分开：标题、卡片边框只在开机或切页时绘制；温湿度等数值只有发生变化时才刷新。

作用是减少 FSMC 写显存次数，降低闪屏，也减少 LCD 任务占用 CPU 的时间。底部提示条由 `AppUi_DrawFooter()` 统一绘制，避免两个页面复制同样的代码。

### 8.2 KEY1 消抖

机械按键在按下或松开瞬间会产生多次抖动。`app_key.c` 使用 `APP_KEY_DEBOUNCE_MS`（30 ms）：电平变化后必须保持 30 ms 才认定为一次有效变化。

KEY1 是低电平有效，因此 `AppKey_PageTogglePressed()` 只有在稳定变为低电平时返回 `true`。UI 任务收到 `true` 后调用 `AppUi_TogglePage()`。

## 9. ESP32 UART 单一字节流

### 9.1 当前边界

ESP32 由 Arduino IDE 独立烧录，负责 Wi-Fi、MQTT、华为云事件和固件下载。STM32 通过 USART2 发送环境文本，并接收 STATUS 文本与 OTA 二进制帧。

`esp32_uart.c` 只保留三个传输接口：

| 函数 | 作用 |
| --- | --- |
| `Esp32Uart_Init()` | 清空 256 字节环形缓冲区并启动单字节接收中断。 |
| `Esp32Uart_SendString()` | 最长等待 100 ms，发送一个以 `\0` 结尾的字符串。 |
| `Esp32Uart_ReadByte()` | 非阻塞取出一个已接收字节；无数据立即返回 `false`。 |

### 9.2 为什么只有 OTA 任务读取字节

HAL 回调每收到一个字节就写入环形缓冲区，并立即重新启动下一字节中断：

```c
HAL_UART_Receive_IT(&huart2, &g_rx_byte, 1U);
```

`OtaPort_ReadByte()` 再调用 `Esp32Uart_ReadByte()`，所以 `OtaUart_Process()` 是唯一消费者。它在空闲状态拼接 `STATUS`/`OTA_BEGIN` 文本，在升级状态解析二进制帧。不能再增加第二个读取任务，否则两个任务会分走同一条字节流。

普通环境数据仍由遥测任务发送：

```c
Esp32Uart_SendString("ENV,25.3,60.1,350,42\r\n");
```

接收中断不得解析字符串、绘制 LCD 或写 Flash；这些耗时操作都留在 OTA 任务上下文完成。

## 10. CubeMX 安全修改指南

### 10.1 必须保存的配置

`42_lcd_hal.ioc` 是 CubeMX 配置源文件。当前配置包括 ADC1、I2C1、FSMC、USART2 和四个 FreeRTOS 任务。`ProjectManager.KeepUserCode=true` 允许 CubeMX 尽量保留用户代码区。

### 10.2 可以安全写代码的位置

在 CubeMX 生成文件中，自己的代码写在以下区域：

```c
/* USER CODE BEGIN Includes */
/* USER CODE END Includes */

/* USER CODE BEGIN 2 */
/* USER CODE END 2 */
```

`main.c` 中的 `LCD_Init()` 和 `Board_Esp32Enable_Init()` 就位于 `USER CODE BEGIN 2`。`freertos.c` 中每个任务的循环逻辑也位于对应的 `USER CODE` 区。

自写的 `dht11.c`、`env_sensor.c`、`app_ui.c`、`esp32_uart.c` 等独立模块不是 CubeMX 生成文件，重新生成代码不会删除它们。

### 10.3 重新生成后的检查清单

1. 检查 `ProjectManager.KeepUserCode=true` 仍然存在。
2. 检查 `main.c` 的 `USER CODE BEGIN Includes` 和 `USER CODE BEGIN 2` 中的代码仍在。
3. 检查 `freertos.c` 三个任务的 `USER CODE BEGIN Start...` 内容仍在。
4. 检查 Keil 工程仍包含自写 `.c` 文件，尤其是 `esp32_uart.c`。
5. Rebuild 后确认 `0 Error(s), 0 Warning(s)`。

## 11. 常见问题与排错

| 现象 | 优先检查 | 原因 |
| --- | --- | --- |
| LCD 白屏或蓝屏 | FSMC 配置、供电、`LCD_Init()` 是否在 USER CODE 区执行 | LCD 尚未完成硬件初始化或总线配置不匹配。 |
| LCD 显示 `NO DATA` | 传感器供电、地线、I2C 地址、PC3、ADC 输入 | 对应模块返回 `false`，这是防止显示假数据的保护。 |
| KEY1 无法切页 | PF8 接线、低电平有效、30 ms 消抖 | 按键没有被识别为稳定的低电平。 |
| ESP32 没有状态 | PA2/PA3 是否交叉、共地、115200 波特率、接收中断是否持续重启 | STATUS 文本必须以换行结束并由 `otaTask` 从环形缓冲区解析。 |
| 系统启动后停住 | 传感器初始化位置、FreeRTOS 堆、任务创建结果 | 传感器初始化必须在传感器任务内，任务创建失败会进入 `Error_Handler()`。 |

## 12. A/B OTA 与系统状态页

当前工程已经实现 A/B OTA，不再是占位设计。ESP32 下载固件后，通过 `OTA_BEGIN`、二进制帧和 `OTA_END` 把镜像写入 STM32 的非活动槽位；STM32 校验 SHA-256、CRC32 和向量表后写入 pending 元数据并复位。

Bootloader 试启动新槽位；应用稳定运行 10 秒后由 `otaTask` 确认并发送 `BOOT_OK`。ESP32 只有收到版本匹配的 `BOOT_OK` 才向华为云报告 100%。`SYSTEM STATUS` 页面显示 Wi-Fi、MQTT、OTA 进度、结果消息和当前版本。

网络下载属于 ESP32，Flash 擦写属于 STM32 OTA 任务，LCD 绘制属于 UI 任务。三个职责保持分离，避免网络等待或 Flash 操作破坏显示和传感器采样。
