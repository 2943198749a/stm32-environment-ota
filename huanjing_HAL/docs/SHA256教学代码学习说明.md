# SHA-256 教学代码学习说明

这份文档面向正在学习 C 语言和 STM32 OTA 的读者，讲解“一次性输入数据，输出 32 字节摘要”的教学版本。先解释术语和运算，再逐个分析函数，最后附上完整代码、验证方法和练习。

**学习目标：知道数据如何被分组、怎样更新计算状态、为什么要填充，以及如何得到和验证摘要。** 第一遍不要求背下 64 个常量，也不要求推导密码学原理。

推荐阅读路线：第 1～3 节打基础 → 第 4 节看整体 → 第 5～9 节逐函数学习 → 第 10 节手算 `abc` 的数据布局 → 第 11 节验证 → 第 12 节对应 OTA。完整代码在附录 A。

## 1. 先理解专业词汇

### 1.1 位、字节、整数和十六进制

| 名称 | 意思 | 本文中的例子 |
|---|---|---|
| 位，bit | 一个二进制位置，只能为 0 或 1 | `1` |
| 字节，byte | 本文使用的环境中，1 字节是 8 位 | `10101011` |
| 十六进制 | 用 `0～9`、`a～f` 表示数值，C 中通常加 `0x` 前缀 | `0xAB` |
| 高位 | 数值权重较大的位，通常画在左侧 | `10000000` 中最左侧的 1 |
| 低位 | 数值权重较小的位，通常画在右侧 | `00000001` 中最右侧的 1 |
| 32 位字，word | SHA-256 中一个 32 位无符号整数，等于 4 字节 | `uint32_t` |

一个十六进制数字对应 4 个二进制位，因此两个十六进制数字表示一个字节：

```text
十六进制： A    B
二进制：  1010 1011

0xAB = 171（十进制）
```

`uint8_t` 表示 8 位无符号整数，范围为 0～255；`uint32_t` 表示 32 位无符号整数，范围为 0～2³²−1。`uint64_t` 是 64 位无符号整数。

### 1.2 大端和小端：多个字节怎样排列

先区分**一个整数的数值**和**这个整数的字节如何存放**。

对于数值 `0x12345678`，它由四个字节组成：`12`、`34`、`56`、`78`。

| 连续地址 | 大端存放 | 小端存放 |
|---|---|---|
| 地址 N，最低地址 | `0x12` | `0x78` |
| 地址 N+1 | `0x34` | `0x56` |
| 地址 N+2 | `0x56` | `0x34` |
| 地址 N+3，最高地址 | `0x78` | `0x12` |

- **大端，big-endian：高位字节放在低地址。**
- **小端，little-endian：低位字节放在低地址。**

这里改变的是四个字节的顺序，不是把每个字节里的二进制位倒过来。大端和小端表示的整数仍然可以是同一个 `0x12345678`。

你这块 STM32 使用小端存储，而 SHA-256 要按大端规则解释分组中的 32 位字、写入末尾长度、输出摘要。因此代码显式使用移位和拼接进行转换。

**不能直接把输入字节指针强制转换为 `uint32_t *` 再读取来代替大端拼接**：除了字节序，还涉及地址对齐和 C 的对象访问规则。

### 1.3 消息、分组、消息字、状态和摘要

| 术语 | 含义 | 对应变量 |
|---|---|---|
| 消息，message | 要计算摘要的原始数据，可以是字符串，也可以是 BIN 固件 | `data` |
| 分组，block | 算法一次处理的 64 字节数据 | `block[64]` |
| 消息字 | 一个 32 位整数；一组先拆成 16 个，再扩展成 64 个 | `w[64]` |
| 状态，state | 已处理数据留下的累计计算结果 | `H[8]` |
| 轮，round | 分组内部的一次固定计算步骤；每组执行 64 轮 | `for (i = 0; i < 64; i++)` |
| 摘要，digest | 对整份消息计算后输出的固定长度结果 | `digest[32]` |
| 填充，padding | 在消息末尾添加算法规定的标记、零和长度 | `tail[128]` |
| 增量计算 | 分多次输入数据，持续保留计算状态 | 工程中的 `Update()` |

SHA-256 的输出长度是 256 位，也就是 32 字节。用十六进制文本表示时，每字节需要两个字符，因此是 64 个字符。

```c
uint8_t digest[32]; // 二进制摘要
char hex[65];       // 64 个十六进制字符，加一个 '\0'
```

摘要不是加密后的原文件，不能靠“解密摘要”恢复 BIN。摘要匹配用于检查内容是否符合预期；它本身不能证明固件来自可信发布者，如果固件和预期摘要都被替换，仅做摘要比较不能认证来源。

### 1.4 “压缩函数”不是压缩文件

本文中的分组压缩，是把“当前 256 位状态”和“当前 512 位分组”运算成新的 256 位状态。它不是 ZIP 压缩，不保留可恢复原文件的压缩包。

## 2. 按位运算：先用 8 位例子看懂

以下用 8 位图方便观察。**教学代码的核心变量是 `uint32_t`，实际运算宽度为 32 位。**

### 2.1 按位与 `&`：两个对应位都是 1，结果才是 1

```text
   1100 1010   0xCA
&  1010 1100   0xAC
------------
   1000 1000   0x88
```

常见用途是保留某些位、清除其他位。例如只保留一个字节的低 4 位：

```text
   1010 1011   0xAB
&  0000 1111   0x0F
------------
   0000 1011   0x0B
```

```c
uint32_t low = 0xABU & 0x0FU; // 得到 11
```

`0x0F` 在这里叫“掩码”：哪些位置写 1，就保留原数的哪些位置。

### 2.2 按位或 `|`：两个对应位有一个是 1，结果就是 1

```text
   1100 1010   0xCA
|  1010 1100   0xAC
------------
   1110 1110   0xEE
```

常见用途是把已经放在不同位置的位组合起来：

```text
   1010 0000   0xA0
|  0000 1011   0x0B
------------
   1010 1011   0xAB
```

SHA-256 中把四个字节拼成一个整数，就用到了按位或。

### 2.3 按位异或 `^`：对应位不同为 1，相同为 0

```text
   1100 1010   0xCA
^  1010 1100   0xAC
------------
   0110 0110   0x66
```

可以记住：`x ^ 0 = x`，`x ^ x = 0`。这里的 `^` **不是乘方**。

### 2.4 按位取反 `~`：每一位都翻转

8 位示意：

```text
原值： 1100 1010
取反： 0011 0101
```

真正的 32 位例子：

```c
uint32_t x = 0x000000CAU;
uint32_t y = ~x; // y = 0xFFFFFF35
```

注意整数提升：如果对 `uint8_t` 直接使用 `~`，C 通常会先把它提升为 `int`。不要把上面的 8 位示意误当作所有 C 表达式都只在 8 位内运算。

### 2.5 按位运算与逻辑运算的区别

| 表达式 | 含义 | 示例结果 |
|---|---|---|
| `2U & 1U` | 对每一位做与运算 | `0` |
| `2U && 1U` | 两个数都非零，则逻辑为真 | `1` |
| `2U | 1U` | 对每一位做或运算 | `3` |
| `2U || 1U` | 至少一个数非零，则逻辑为真 | `1` |

`&&`、`||` 用于条件判断，并有短路行为。`&`、`|` 是按位运算，不提供这种逻辑短路行为。

同一个 `&` 还可能表示取地址：

```c
x & mask  // 两个操作数：按位与
&x        // 一个操作数：取得 x 的地址
```

### 2.6 左移、右移和循环右移

对于本代码的无符号数：

- `x << n`：向左移动 n 位，低位补零。
- `x >> n`：向右移动 n 位，高位补零。
- 循环右移：右侧移出去的位，重新放到左侧。

```c
0x00000012U << 8  // 0x00001200
0x12345678U >> 8  // 0x00123456
```

循环右移的 32 位例子：

```text
原值：     00000000 00000000 00000000 00000001
普通右移： 00000000 00000000 00000000 00000000
循环右移： 10000000 00000000 00000000 00000000
```

循环右移结果是 `0x80000000`。循环右移会保留所有位，只是改变位置。

### 2.7 32 位加法：只保留低 32 位

SHA-256 的加法按模 2³² 计算。对于本文实现使用的 32 位无符号运算，可以理解为“超过 32 位的进位不保留”：

```text
0xFFFFFFFF + 1 → 0x00000000
```

这是算法需要的行为。不要擅自把状态改成有符号 `int32_t`，有符号溢出不具备同样的 C 语言保证。

## 3. 阅读代码需要的 C 语言基础

| 写法 | 含义 |
|---|---|
| `uint32_t H[8]` | 8 个 32 位无符号整数，共 32 字节 |
| `uint8_t tail[128] = {0}` | 建立 128 字节数组，全部初始化为零 |
| `const uint8_t *data` | 通过此指针读取字节数据，不通过它修改数据 |
| `data += 64` | 指针移动到后面的第 64 个字节 |
| `size_t` | C 中用于表达对象大小等信息的无符号整数类型 |
| `static` 放在函数前 | 函数只在当前源文件内部可见 |
| `(uint32_t)p[0]` | 把一个字节转换成 32 位无符号数 |
| `0x80U` | 十六进制无符号整数常量 |
| `sizeof(text) - 1` | 对本文的字符串数组，排除末尾的 `\0` |

函数参数中的 `uint8_t digest[32]` 实际按指针参数处理，不会在函数里自动创建 32 字节数组，也不会自动检查调用者是否提供了 32 字节空间。调用者需要自己声明：

```c
uint8_t digest[32];
sha256(data, length, digest);
```

这个教学版的算法函数默认调用参数符合约定：输出数组有效；非零长度输入指针有效；输入长度小于 2⁶¹ 字节，以便原始位长度能装入 64 位字段。它没有完整的错误返回接口。

## 4. 整体结构：先看每个函数负责什么

```text
main：准备输入，调用算法，打印结果
  └─ sha256：初始化、分组、填充、输出
       ├─ process_block：处理一个完整的 64 字节分组
       │    ├─ read_be32：把 4 字节组合成一个整数
       │    └─ rotr：循环右移
       └─ write_be32：把一个整数输出成 4 字节
```

| 函数 | 输入 | 结果/副作用 |
|---|---|---|
| `rotr(x, n)` | 一个 32 位整数、移位次数 | 返回循环右移结果 |
| `read_be32(p)` | 至少 4 个可读字节 | 返回按大端组合的整数 |
| `write_be32(p, value)` | 至少 4 字节输出空间、一个整数 | 写入 4 字节 |
| `process_block(H, block)` | 8 个状态值、64 字节数据 | 更新状态 H |
| `sha256(data, length, digest)` | 整段输入及其字节数 | 写入 32 字节摘要 |
| `main()` | 测试字符串 | 打印摘要 |

这里的“一次性”是指调用者一次提供完整的输入范围。算法仍然逐个分组处理，不会建立与整个输入一样大的临时数组。

## 5. `rotr()`：循环右移

```c
static uint32_t rotr(uint32_t x, unsigned int n)
{
    return (x >> n) | (x << (32U - n));
}
```

拆成三步：

1. `x >> n`：把主体移到右侧，高位先补零。
2. `x << (32 - n)`：把应当绕回去的低位移到最高端。
3. `|`：合并两部分。

例如 `x = 0x12345678`、`n = 8`：

```text
x >> 8      = 0x00123456
x << 24     = 0x78000000（保留 32 位）
按位或结果  = 0x78123456
```

本函数只适用于 `n` 为 1～31 的调用。若传入 0，就会出现左移 32 位，对 32 位运算对象不是合法的移位次数。教学代码内部没有这样的调用。

## 6. `read_be32()` 和 `write_be32()`：字节与整数互换

### 6.1 读取大端整数

```c
return ((uint32_t)p[0] << 24U) |
       ((uint32_t)p[1] << 16U) |
       ((uint32_t)p[2] << 8U)  |
       (uint32_t)p[3];
```

假设 `p` 指向字节序列 `12 34 56 78`：

```text
p[0] << 24 → 0x12000000
p[1] << 16 → 0x00340000
p[2] <<  8 → 0x00005600
p[3]       → 0x00000078
-------------------------------- 按位或
             0x12345678
```

显式转换为 `uint32_t` 后再移位，可以让拼接按所需的无符号宽度进行，尤其是最高字节左移 24 位时。

### 6.2 输出大端字节

```c
p[0] = (uint8_t)(value >> 24U);
p[1] = (uint8_t)(value >> 16U);
p[2] = (uint8_t)(value >> 8U);
p[3] = (uint8_t)value;
```

对于 `value = 0x12345678`：

| 操作 | 移位后数值 | 转成 `uint8_t` 后 |
|---|---|---|
| `value >> 24` | `0x00000012` | `0x12` |
| `value >> 16` | `0x00001234` | `0x34` |
| `value >> 8` | `0x00123456` | `0x56` |
| 不移位 | `0x12345678` | `0x78` |

转换成 `uint8_t` 后保留低 8 位，所以不用再额外写 `& 0xFF`。

## 7. `process_block()`：一个分组如何改变状态

```c
static void process_block(uint32_t H[8], const uint8_t block[64])
```

`H` 是跨分组保留的状态；`block` 是当前需要处理的 64 字节。函数不产生完整文件的最终摘要，而是推进一次分组计算。

### 7.1 从 64 字节得到 16 个消息字

```c
for (i = 0; i < 16; i++)
{
    w[i] = read_be32(block + i * 4U);
}
```

```text
block[ 0.. 3] → w[0]
block[ 4.. 7] → w[1]
……
block[60..63] → w[15]
```

每 4 字节形成一个 32 位整数，一共 16 个。

### 7.2 从 16 个消息字扩展到 64 个

后面的每一项按下面的固定公式生成：

```c
x = w[i - 15];
y = w[i - 2];
s0 = rotr(x, 7) ^ rotr(x, 18) ^ (x >> 3);
s1 = rotr(y, 17) ^ rotr(y, 19) ^ (y >> 10);
w[i] = w[i - 16] + s0 + w[i - 7] + s1;
```

第一次 `i = 16` 时，使用的是 `w[0]`、`w[1]`、`w[9]`、`w[14]`，它们都已经生成。后续迭代也只依赖已生成的内容。

这一步只是准备内部运算材料，不会扩充原文件，也不会把这些扩展值写入 Flash。

### 7.3 将 H 复制到工作变量 a～h

```c
a = H[0]; b = H[1]; c = H[2]; d = H[3];
e = H[4]; f = H[5]; g = H[6]; h = H[7];
```

`H` 保存本组计算开始前的状态；`a～h` 在 64 轮中不断变化。结束后还需要把两者相加，因此不能在一开始丢掉原 H。

### 7.4 一轮运算中的 choose 和 majority

选择函数：

```c
ch = (e & f) ^ ((~e) & g);
```

对每个二进制位置分别看：当 e 的这一位为 1 时取 f；为 0 时取 g。

```text
e = 1100
f = 1010
g = 0101
---------
ch= 1001
```

多数函数：

```c
maj = (a & b) ^ (a & c) ^ (b & c);
```

每个位置上，a、b、c 中至少两个为 1，结果为 1。

```text
a   = 1100
b   = 1010
c   = 0110
-----------
maj = 1110
```

### 7.5 S0、S1、t1、t2 和 64 轮

```c
S1 = rotr(e, 6) ^ rotr(e, 11) ^ rotr(e, 25);
t1 = h + S1 + ch + K[i] + w[i];
S0 = rotr(a, 2) ^ rotr(a, 13) ^ rotr(a, 22);
t2 = S0 + maj;
```

- `S0`、`S1`：对工作变量做循环移位和异或。
- `K[i]`：当前轮的固定常量，不是密钥。
- `w[i]`：当前轮使用的消息字。
- `t1`、`t2`：本轮临时结果。

然后更新工作变量：

```c
h = g; g = f; f = e; e = d + t1;
d = c; c = b; b = a; a = t1 + t2;
```

这些语句按顺序执行。**不要随意把更新顺序倒过来**，否则可能提前覆盖后面还要使用的旧值。

扩展消息时的小写 `s0/s1` 与轮运算中的大写 `S0/S1` 是不同公式，循环移位的次数也不同。

### 7.6 把工作结果加回 H

```c
H[0] += a; H[1] += b; H[2] += c; H[3] += d;
H[4] += e; H[5] += f; H[6] += g; H[7] += h;
```

下一组使用更新后的 H。不能每组都重新初始化，也不能用 `H[0] = a` 替代 `H[0] += a`。

## 8. `sha256()`：组织一次完整的计算

### 8.1 初始化 H 并记住原始长度

H 的八个初始值由算法固定规定。`K[64]` 和初始 H 都必须按标准使用。

```c
uint64_t bit_length = (uint64_t)length * 8U;
size_t remaining = length;
```

`length` 是字节数，`bit_length` 是位数。先转换成 `uint64_t` 再相乘，有利于在 32 位系统上保留足够的运算宽度。

`remaining` 后面会逐渐减少，但消息末尾必须写原始消息的位长度，所以要提前保存 `bit_length`。

### 8.2 处理全部完整分组

```c
while (remaining >= 64U)
{
    process_block(H, data);
    data += 64U;
    remaining -= 64U;
}
```

例如输入 150 字节：处理前 64 字节，再处理后面的 64 字节，最后剩 22 字节。此时 `data` 已经指向这 22 字节的开头。

### 8.3 复制尾部，追加 0x80

```c
uint8_t tail[128] = {0};

if (remaining > 0U)
{
    memcpy(tail, data, remaining);
}
tail[remaining] = 0x80U;
```

`0x80` 是二进制 `10000000`，实现“先追加一个 1 位”。数组已经全清零，后面的空位自然是零。

填充只发生在计算缓冲区，不会改动输入数据，也不会给 BIN 固件追加这些内容。

### 8.4 为什么用 56 判断是否需要两个分组

每组 64 字节，最后必须保留 8 字节保存原始位长度。因此前面最多使用 56 字节。

但原始尾部后还要放一个 `0x80`，所以：

```text
剩余数据 ≤ 55 字节：一组能装下
剩余数据 ≥ 56 字节：需要两组
```

```c
padded_length = (remaining < 56U) ? 64U : 128U;
```

这是三目运算符：条件为真选 64，否则选 128。

| 原始总长度 | 先处理完整分组数 | 原始尾部字节数 | 填充分组数 | 最终处理的分组总数 |
|---:|---:|---:|---:|---:|
| 0 | 0 | 0 | 1 | 1 |
| 3 | 0 | 3 | 1 | 1 |
| 55 | 0 | 55 | 1 | 1 |
| 56 | 0 | 56 | 2 | 2 |
| 63 | 0 | 63 | 2 | 2 |
| 64 | 1 | 0 | 1 | 2 |
| 65 | 1 | 1 | 1 | 2 |
| 150 | 2 | 22 | 1 | 3 |

**原始长度正好为 64 的整数倍，也必须另加填充分组。** 空消息同样需要填充。

### 8.5 在末尾写入 8 字节位长度

```c
for (i = 0; i < 8; i++)
{
    tail[padded_length - 1U - i] =
        (uint8_t)(bit_length >> (i * 8U));
}
```

循环从数组末尾往前写，先写最低字节，再写更高的字节。最终从低地址到高地址看，就是大端排列。

对于 `abc`，`bit_length = 24 = 0x18`，最后 8 字节是：

```text
00 00 00 00 00 00 00 18
```

随后处理一个或两个填充分组。

### 8.6 输出摘要

```c
for (i = 0; i < 8; i++)
{
    write_be32(digest + i * 4U, H[i]);
}
```

8 个状态值，每个输出 4 字节，共 32 字节。这里不生成字符串，只生成二进制摘要。

## 9. `main()`：输入是什么，打印的又是什么

```c
const char text[] = "abc";
uint8_t digest[32];
sha256((const uint8_t *)text, sizeof(text) - 1U, digest);
```

`text` 数组实际上有 4 个字节：`'a'`、`'b'`、`'c'`、`'\0'`。这里计算的是三个字符的摘要，所以排除结束符。

`sizeof(text) - 1` 适用于这里的数组。若 `text` 改成指针，`sizeof(text)` 得到的是指针大小。处理 BIN 时也不能用 `strlen()`，因为 BIN 中可以包含 `0x00`，应使用真实的固件字节数。

```c
printf("%02x", (unsigned int)digest[i]);
```

- `%x`：按小写十六进制打印。
- `2`：最少打印两位。
- `0`：不足两位时在前面补零。

例如字节 `0x05` 打印为 `05`，不会只打印成 `5`。逐个打印 32 字节，得到 64 个字符。

打印没有改变摘要内容，只是把它换成方便人阅读的表示。

## 10. 跟着 `abc` 看一次完整的数据流

### 第一步：原始输入

```text
data = 61 62 63
length = 3 字节
bit_length = 24 位
```

### 第二步：初始化，跳过完整原始分组循环

设置八个 H 初始值。因为 3 < 64，没有可以直接处理的完整原始分组。

### 第三步：构造一个填充分组

```text
字节下标  0   1   2   3   4 ........ 55   56 ....... 62   63
字节内容 61  62  63  80  00 ........ 00   00 ....... 00   18
```

### 第四步：读取前 16 个消息字

```text
w[0]  = 0x61626380
w[1]  到 w[14] = 0x00000000
w[15] = 0x00000018
```

注意 `w[15]` 是 24，而不是 3，因为长度字段的单位是位。

### 第五步：扩展消息，执行 64 轮，更新 H

生成 `w[16]～w[63]`，再通过 64 轮修改 `a～h`，最后加回 H。

### 第六步：输出并打印 32 字节摘要

预期十六进制结果：

```text
ba7816bf8f01cfea414140de5dae2223b00361a396177a9cb410ff61f20015ad
```

可以在调试器里给 `process_block()` 打断点，先核对 `w[0]` 和 `w[15]`，确认填充和大端读取正确，再研究轮运算。

## 11. 验证方法和常见错误

### 11.1 先做两个基本测试

| 输入 | 长度 | 调用方式 |
|---|---:|---|
| `abc` | 3 | 附录中的 `main()` |
| 空消息 | 0 | `sha256(NULL, 0, digest)` |

空消息的预期摘要：

```text
e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855
```

两个基本测试用于快速检查，不能替代边界测试。

### 11.2 再检查 55、56、63、64、65 字节边界

用 Python 标准库生成参考值：

```python
import hashlib

for length in [0, 3, 55, 56, 63, 64, 65, 1000]:
    data = b"a" * length
    print(length, hashlib.sha256(data).hexdigest())
```

在 C 中使用相同输入。可以暂时把附录中的 `main()` 替换为：

```c
int main(void)
{
    static const size_t lengths[] = {0, 3, 55, 56, 63, 64, 65, 1000};
    uint8_t input[1000];
    uint8_t digest[32];
    size_t t;
    unsigned int i;

    memset(input, 'a', sizeof(input));

    for (t = 0; t < sizeof(lengths) / sizeof(lengths[0]); t++)
    {
        sha256(input, lengths[t], digest);
        printf("%zu ", lengths[t]);
        for (i = 0; i < 32; i++)
        {
            printf("%02x", (unsigned int)digest[i]);
        }
        printf("\n");
    }
    return 0;
}
```

这里 3 字节测试是 `aaa`，与前面的 `abc` 不同，不要比较错输入。

若电脑已安装 GCC，可将附录代码保存为 `sha256_demo.c`，使用：

```powershell
gcc -std=c99 -Wall -Wextra sha256_demo.c -o sha256_demo.exe
.\sha256_demo.exe
```

这是可自行执行的验证步骤，不代表已在你的 STM32 硬件上验证。该 `main()` 用于电脑测试；放入 STM32 工程时不要再添加一个与工程冲突的 `main()`，打印也需要相应输出支持。

### 11.3 根据现象定位错误

| 现象 | 优先检查 |
|---|---|
| `abc` 就不正确 | 常量、初始值、大端拼接、位运算公式、字符串长度 |
| 55 字节正确，56 字节错误 | 是否正确切换为两个填充分组 |
| 63 字节正确，64 字节错误 | 是否为整组输入另加了填充分组 |
| 短输入正确，长输入错误 | 是否每组错误地重置 H，指针是否移动正确 |
| 输出少于 64 个字符 | 是否遗漏 `%02x` 中的补零 |
| 文本正常，BIN 异常 | 是否误用 `strlen()`，或把数据当作有符号字节 |
| 与文件工具的摘要不同 | 是否输入了相同文件字节，是否多算了换行或 `\0` |

## 12. 对照当前 OTA 工程学习

对应文件：

- `huanjing_HAL/user/OTA/Inc/sha256.h`：上下文和接口。
- `huanjing_HAL/user/OTA/Src/sha256.c`：增量计算实现。
- `huanjing_HAL/user/OTA/Src/ota_app.c`：OTA 中的实际调用。

| 教学版 | 工程版 | 共同用途 |
|---|---|---|
| `rotr()` | `Sha256_RotateRight()` | 循环右移 |
| `process_block()` | `Sha256_ProcessBlock()` | 处理 64 字节分组 |
| `sha256()` 中初始化部分 | `Sha256_Init()` | 创建初始状态 |
| `sha256()` 中分组处理部分 | `Sha256_Update()` | 处理输入；工程版另有跨调用的缓存 |
| `sha256()` 中填充、输出部分 | `Sha256_Final()` | 完成并输出摘要 |
| 教学版打印摘要供人检查 | `Sha256_HexEquals()` | 工程版直接与预期文本比较 |

工程中 `OtaApp_Begin()` 调用 Init；每次 `OtaApp_Write()` 写入并读回检查通过后调用 Update；`OtaApp_Finalize()` 调用 Final 和 HexEquals。

```text
一份固件：Init 一次 → Update 多次 → Final 一次 → 比较摘要
```

不能对每个串口包重新 Init，否则最后得到的不是整份固件的摘要。

**三个大小不要混淆：**

| 大小 | 用途 |
|---|---|
| 串口传输块大小 | 通信协议一次传多少固件数据 |
| SHA-256 分组大小：64 字节 | 摘要算法内部一次处理多少数据 |
| 本工程 Flash 页大小：2048 字节 | Flash 一次按页擦除的单位 |

SHA-256 的 64 字节分组不要求串口每次也只发送 64 字节。

Bootloader 在本工程中使用保存的镜像 CRC32 等信息复查镜像；不能把它与应用下载期间的 SHA-256 比较混为一个调用步骤。

## 13. 小练习：先做，再看答案

1. `0xA5 & 0x0F` 是多少？
2. `0xA0 | 0x05` 是多少？
3. `0xA5 ^ 0xFF` 是多少？
4. 字节序列 `01 02 03 04` 按大端读取是多少？
5. `0x12345678` 循环右移 8 位是多少？
6. 60 字节原始消息，填充后需要处理多少组？
7. 64 字节原始消息，总共需要处理多少组？
8. `abc` 的长度字段为什么是 `0x18` 而不是 `0x03`？
9. 输入固件 1000 字节，会先处理多少个完整原始分组，剩下多少字节？
10. 同样内容分一次 Update 和十次 Update，摘要是否应相同？

答案：

1. `0x05`，只保留低四位。
2. `0xA5`。
3. `0x5A`。
4. `0x01020304`。
5. `0x78123456`。
6. 2 组，尾部数据加标记和长度无法放进 1 组。
7. 2 组，1 组原始数据和 1 组填充。
8. 长度字段以位为单位，3 × 8 = 24 = `0x18`。
9. 15 组，剩 40 字节；加 1 个填充分组，总共 16 组。
10. 应相同，前提是字节内容与顺序相同，而且共用同一个持续的计算上下文。

## 附录 A：完整教学代码

此处集中放置可保存为 `sha256_demo.c` 的完整代码，方便与前文对照。它是独立教学版本，不需要替换当前 OTA 中的 `sha256.c`。

```c
#include <stdint.h>
#include <stddef.h>
#include <stdio.h>
#include <string.h>

/* 64 轮固定常量。 */
static const uint32_t K[64] =
{
    0x428a2f98U, 0x71374491U, 0xb5c0fbcfU, 0xe9b5dba5U,
    0x3956c25bU, 0x59f111f1U, 0x923f82a4U, 0xab1c5ed5U,
    0xd807aa98U, 0x12835b01U, 0x243185beU, 0x550c7dc3U,
    0x72be5d74U, 0x80deb1feU, 0x9bdc06a7U, 0xc19bf174U,
    0xe49b69c1U, 0xefbe4786U, 0x0fc19dc6U, 0x240ca1ccU,
    0x2de92c6fU, 0x4a7484aaU, 0x5cb0a9dcU, 0x76f988daU,
    0x983e5152U, 0xa831c66dU, 0xb00327c8U, 0xbf597fc7U,
    0xc6e00bf3U, 0xd5a79147U, 0x06ca6351U, 0x14292967U,
    0x27b70a85U, 0x2e1b2138U, 0x4d2c6dfcU, 0x53380d13U,
    0x650a7354U, 0x766a0abbU, 0x81c2c92eU, 0x92722c85U,
    0xa2bfe8a1U, 0xa81a664bU, 0xc24b8b70U, 0xc76c51a3U,
    0xd192e819U, 0xd6990624U, 0xf40e3585U, 0x106aa070U,
    0x19a4c116U, 0x1e376c08U, 0x2748774cU, 0x34b0bcb5U,
    0x391c0cb3U, 0x4ed8aa4aU, 0x5b9cca4fU, 0x682e6ff3U,
    0x748f82eeU, 0x78a5636fU, 0x84c87814U, 0x8cc70208U,
    0x90befffaU, 0xa4506cebU, 0xbef9a3f7U, 0xc67178f2U
};

/* n 必须为 1～31。 */
static uint32_t rotr(uint32_t x, unsigned int n)
{
    return (x >> n) | (x << (32U - n));
}

static uint32_t read_be32(const uint8_t *p)
{
    return ((uint32_t)p[0] << 24U) |
           ((uint32_t)p[1] << 16U) |
           ((uint32_t)p[2] << 8U) |
           (uint32_t)p[3];
}

static void write_be32(uint8_t *p, uint32_t value)
{
    p[0] = (uint8_t)(value >> 24U);
    p[1] = (uint8_t)(value >> 16U);
    p[2] = (uint8_t)(value >> 8U);
    p[3] = (uint8_t)value;
}

static void process_block(uint32_t H[8], const uint8_t block[64])
{
    uint32_t w[64];
    uint32_t a, b, c, d, e, f, g, h;
    unsigned int i;

    /* 64 字节转换为 16 个消息字。 */
    for (i = 0; i < 16; i++)
    {
        w[i] = read_be32(block + i * 4U);
    }

    /* 扩展到 64 个消息字。 */
    for (i = 16; i < 64; i++)
    {
        uint32_t x = w[i - 15];
        uint32_t y = w[i - 2];
        uint32_t s0 = rotr(x, 7) ^ rotr(x, 18) ^ (x >> 3);
        uint32_t s1 = rotr(y, 17) ^ rotr(y, 19) ^ (y >> 10);
        w[i] = w[i - 16] + s0 + w[i - 7] + s1;
    }

    a = H[0]; b = H[1]; c = H[2]; d = H[3];
    e = H[4]; f = H[5]; g = H[6]; h = H[7];

    /* 64 轮。 */
    for (i = 0; i < 64; i++)
    {
        uint32_t S1 = rotr(e, 6) ^ rotr(e, 11) ^ rotr(e, 25);
        uint32_t ch = (e & f) ^ ((~e) & g);
        uint32_t t1 = h + S1 + ch + K[i] + w[i];
        uint32_t S0 = rotr(a, 2) ^ rotr(a, 13) ^ rotr(a, 22);
        uint32_t maj = (a & b) ^ (a & c) ^ (b & c);
        uint32_t t2 = S0 + maj;

        h = g;
        g = f;
        f = e;
        e = d + t1;
        d = c;
        c = b;
        b = a;
        a = t1 + t2;
    }

    H[0] += a; H[1] += b; H[2] += c; H[3] += d;
    H[4] += e; H[5] += f; H[6] += g; H[7] += h;
}

/*
 * data 在 length > 0 时必须有效；length 必须小于 2^61。
 * digest 必须提供至少 32 字节可写空间。
 * length 为 0 时允许 data 为 NULL。
 */
void sha256(const uint8_t *data, size_t length, uint8_t digest[32])
{
    uint32_t H[8] =
    {
        0x6a09e667U, 0xbb67ae85U,
        0x3c6ef372U, 0xa54ff53aU,
        0x510e527fU, 0x9b05688cU,
        0x1f83d9abU, 0x5be0cd19U
    };
    uint8_t tail[128] = {0};
    uint64_t bit_length = (uint64_t)length * 8U;
    size_t remaining = length;
    size_t padded_length;
    unsigned int i;

    /* 处理完整原始分组。 */
    while (remaining >= 64U)
    {
        process_block(H, data);
        data += 64U;
        remaining -= 64U;
    }

    /* 复制尾部并填充。 */
    if (remaining > 0U)
    {
        memcpy(tail, data, remaining);
    }
    tail[remaining] = 0x80U;
    padded_length = (remaining < 56U) ? 64U : 128U;

    for (i = 0; i < 8; i++)
    {
        tail[padded_length - 1U - i] =
            (uint8_t)(bit_length >> (i * 8U));
    }

    process_block(H, tail);
    if (padded_length == 128U)
    {
        process_block(H, tail + 64U);
    }

    /* 输出 32 字节摘要。 */
    for (i = 0; i < 8; i++)
    {
        write_be32(digest + i * 4U, H[i]);
    }
}

int main(void)
{
    const char text[] = "abc";
    uint8_t digest[32];
    unsigned int i;

    sha256((const uint8_t *)text, sizeof(text) - 1U, digest);
    for (i = 0; i < 32; i++)
    {
        printf("%02x", (unsigned int)digest[i]);
    }
    printf("\n");
    return 0;
}
```
