# 智能环境检测设计说明

## 目标

基于 STM32F103ZET6 尚硅谷开发板、HAL 和现有 FSMC LCD 驱动，完成一个两页环境检测演示。当前不连接外部传感器，使用平滑变化的模拟数据；安装硬件后，仅替换各传感器驱动的读取函数。

## 已确认的硬件连接

| 功能 | 模块 | STM32 引脚 | 原理图依据 |
| --- | --- | --- | --- |
| 温湿度 | DHT11 | PC3 | 板载 18B20 插座 DATA，可复用 GPIO |
| 光照 | BH1750 | PB6/PB7 (I2C1) | 与板载 EEPROM 使用的 I2C2 PB10/PB11 不冲突 |
| 空气质量 | MQ-135 AO | PC0 (ADC1_IN10) | 板载模拟量输入 |
| 页面切换 | KEY1 | PF8 | 原理图第 8 页确认；PF11 对应 KEY4 |
| Wi-Fi/云上传 | 板载 ESP32-C3 | USART2 PA2/PA3 | ESP32-C3 原理图页固定连接 |
| 显示 | 板载 LCD | FSMC | 保持既有 lcd.c 驱动 |

所有外部模块供电采用 3.3V。MQ-135 若模块 AO 输出为 5V，必须先经电阻分压再接 PC0，禁止直接连接。

## 架构

`env_sensor` 维护统一的环境数据结构并提供模拟值与真实读取入口；`esp32_c3` 封装 AT 指令、Wi-Fi 状态和华为云 MQTT 发布流程；`app_ui` 只负责两页 LCD 渲染；`app_key` 只负责按键消抖和页面切换。main.c 定时调度这些模块，不含业务细节。

## 页面与数据流

KEY1 短按在两个页面间切换。每秒更新一次环境数据和第一页；每五秒尝试发送一次 MQTT 数据。第二页显示 Wi-Fi、MQTT、上传次数与最近结果。ESP32 未实际联网时，模拟模式仍显示可验证的状态机和待发送 JSON；真实模式下发送 AT 命令完成连接和发布。

## 错误处理与测试

每个外设函数返回 HAL_StatusTypeDef 或模块状态；LCD 保持可刷新，通信失败仅更新第二页状态，不阻塞主循环。代码使用固定长度缓存，JSON 长度受限。通过 Keil 编译、静态接口检查和串口日志验证模拟刷新、翻页和模拟上传序列。

## 编码约束

- 使用 STM32 HAL；保持 CubeMX USER CODE 区域可再生成。
- 所有新增 C 函数、重要变量、AT 指令和硬件替换点都写中文注释。
- 不修改 lcd.c 的底层 LCD 驱动。
- 不新增动态内存、RTOS 或第三方库。
